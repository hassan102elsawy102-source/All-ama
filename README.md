# منصة العلّامة | الأستاذ حسن حمدي

منصة تعليمية عربية (RTL) مبنية على واجهة ثابتة (HTML/CSS/JS) + Supabase (قاعدة بيانات PostgreSQL + مصادقة + تخزين).
كل الحماية الفعلية في **قاعدة البيانات** (RLS + دوال خادمية)، وليس في إخفاء الأزرار.

## بنية المشروع
```
supabase/migrations/001_schema.sql   الجداول والعلاقات والفهارس + سياسات RLS + الدوال الإدارية + سجل التدقيق + التخزين
supabase/seed/promote_admin.sql      أمر إنشاء المدير الأول (يدويًا من SQL Editor)
web/                                 الواجهة (انشرها كما هي على أي استضافة ثابتة)
  index.html courses.html course.html auth.html account.html
  admin/index.html                   لوحة المدير
  css/main.css css/admin.css
  js/config.js                       إعدادات الاتصال (أنت تملؤها)
  js/core.js                         وظائف مشتركة
  js/pages/*.js                      صفحات الزوّار والطلاب
  js/admin/*.js                      وحدات لوحة المدير
  _headers                           ترويسات أمان (Netlify / Cloudflare Pages)
docs/SECURITY.md  docs/ACCEPTANCE.md
```

## خطوات التشغيل
1. **إنشاء المشروع:** أنشئ مشروعًا جديدًا على https://supabase.com.
2. **قاعدة البيانات:** افتح SQL Editor والصق محتوى `supabase/migrations/001_schema.sql` ثم Run (مرة واحدة). تأكد أنه انتهى دون أخطاء.
3. **متغيرات البيئة:** من Project Settings → API انسخ `Project URL` والمفتاح العام (anon/publishable) إلى `web/js/config.js`. **لا تضع مفتاح service_role في أي ملف.**
4. **إعداد المصادقة:** Authentication → URL Configuration: ضع رابط موقعك في Site URL وأضفه إلى Redirect URLs (مطلوب لروابط التأكيد واستعادة كلمة المرور). قرّر تفعيل/تعطيل «Confirm email». للبريد الفعلي بكميات حقيقية اربط SMTP خاصًا بك (الخدمة الافتراضية محدودة جدًا).
5. **المدير الأول:** سجّل حسابًا عاديًا من صفحة «إنشاء حساب»، ثم نفّذ `supabase/seed/promote_admin.sql` بعد استبدال البريد. لا توجد أي طريقة لإنشاء مدير من الموقع.
6. **نشر الواجهة:** انشر مجلد `web/` على Netlify أو Cloudflare Pages أو Vercel أو GitHub Pages (مجلد النشر = `web`).
7. **الوظائف الخلفية:** لا يوجد خادم منفصل: العمليات الإدارية الحساسة (منح/سحب الوصول، إعادة الترتيب) هي دوال `security definer` داخل قاعدة البيانات تتحقق من أن المنفّذ مدير. لا حاجة لنشر شيء إضافي.
8. **سياسات الأمان:** تُفعَّل تلقائيًا بتشغيل ملف SQL. تحقق: Table Editor → كل الجداول عليها شارة RLS.
9. **اختبار الدخول والمدير والطلاب:** نفّذ قائمة `docs/ACCEPTANCE.md` بالكامل قبل الإطلاق.

## قرارات التصميم المهمة
- **حماية الدروس:** رابط الفيديو والمرفقات في جدول `lesson_content` منفصل لا يُرجِعه الخادم إلا إذا نجحت `can_view_lesson()` (درس منشور + كورس منشور + [درس مجاني أو كورس مجاني أو صلاحية سارية] + الحساب غير محظور). تغيير الرابط في المتصفح لا يفيد.
- **الحظر:** الطالب المحظور يستطيع تسجيل الدخول ويرى رسالة الحظر، لكنه لا يحصل على أي محتوى دروس (مفروض في RLS).
- **الأدوار:** الدور يُنشأ دائمًا `student` عبر مشغّل في قاعدة البيانات، ومشغّل آخر يمنع أي غير مدير من تعديل `role` أو `is_banned`.
- **الدروس المجانية** تتطلب تسجيل الدخول (حتى يُطبَّق الحظر ويُسجَّل التقدّم).
- **سجل التدقيق** يُكتب من مشغّلات على الخادم عند أي تعديل يقوم به مدير، ولا يستطيع أحد تعديله من الواجهة.

## ما لم يُنفَّذ / حدود معروفة (بصراحة)
- **بوابة الدفع غير موجودة.** زر «الاشتراك» يشرح للطالب أن الدفع غير مفعّل ويعرض بيانات التواصل، والمدير يمنح الصلاحية يدويًا. عمود حالة الدفع يعرض «يدوي» فقط. ربط بوابة (Stripe/Paymob/Fawry…) يحتاج حساب تاجر ووظيفة Webhook على الخادم.
- **حماية الفيديو محدودة بمصدره:** المنصة لا تعرض الرابط إلا لمن يملك الصلاحية، لكن لا تستطيع منع مستخدم مصرّح من مشاركة الرابط إن كان المصدر الخارجي يسمح بذلك. استخدم فيديوهات غير مدرجة (Unlisted) أو تقييد النطاقات (Vimeo) أو خدمة بث محمية.
- **المرفقات روابط** (يلصقها المدير)، وليست رفع ملفات. رفع الصور مدعوم للأغلفة وصور الموقع فقط.
- لم يُجرَّب هذا الكود على مشروع Supabase حي ولم يُشغَّل ملف SQL على PostgreSQL في بيئة الإنشاء (لا شبكة ولا قاعدة بيانات هنا). فُحصت صياغة JavaScript واختُبرت دوال التحقق الأساسية فقط. **لذلك قائمة القبول إلزامية** وقد تظهر تعديلات صغيرة عند أول تشغيل.
- لا يوجد تتبّع لتغيّر البريد الإلكتروني بعد التسجيل (يُنسخ مرة واحدة إلى `profiles`).
